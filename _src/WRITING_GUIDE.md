# How to publish a blog post on workexperiencecalculator.online

The site is static HTML generated by `_src/build.py` into the repo root.
Cloudflare (Worker `workexperiencecalculator`) deploys automatically on every push to `main`.
`_src/` is excluded from the public site by `.assetsignore`.

## Files
- `_src/blog.py` - all posts (list `POSTS`), post path constants (`B1`...), and `SUPPORT` (which calculator page links to which posts).
- `_src/content.py` - the 5 calculator pages. Path constants: HOME `/`, SBOR `/sbor-na-trudov-stazh/`, OSIG `/osiguritelen-stazh/`, PEN `/stazh-za-pensia/`, KLAS `/klas-prosluzheno-vreme/`.
- `_src/build.py` - templates, author (Мария Димитрова), schema, sitemap. Do not change unless needed.
- `_src/TOPICS.md` - topic queue. Take the first `[ ]` topic.

## Adding a post
1. Add a constant `B<n> = "/blog/<latin-slug>/"` (Bulgarian transliterated, lowercase, hyphens).
2. Append a dict to `POSTS` with the same keys as existing posts:
   `path, title (<= 65 chars), desc (140-160 chars), h1, excerpt, tool=(PAGE, "anchor text"), summary=[3 bullets], body (HTML), faq=[3-4 (q, a) tuples, plain text, no HTML]`.
   Optional key `date="YYYY-MM-DD"` (publish date). If missing, the global `DATE` is used.
3. Add the new path to `SUPPORT` for the 1-2 calculator pages it supports (keep max 4 posts per page; replace the weakest match if full).
4. Optionally add ONE natural contextual link to the new post from the most related existing post body.
5. Run `python3 -I _src/build.py` from the repo root. Then run the checks below. Then commit and push.

## Writing rules (all mandatory)
- Language: Bulgarian. Simple words, short sentences, 6th-7th grade reading level. Mix sentence lengths so it reads like a real person wrote it. Talk to the reader as "вие".
- Length: 800-1,200 words of body text. Full search intent: answer the main question in the first 2-3 sentences, then go deeper.
- Structure (Neil Patel / Backlinko style): short hook intro, H2/H3 steps, a worked example in `<div class="example">`, common mistakes or tips, FAQ, CTA (added by template). Short paragraphs (1-3 sentences). Lists where they help.
- Semantic SEO (Koray style): question-style H2s that match real searches, answer first then context, cover the main entity and its attributes (laws: КТ, КСО; institutions: НОИ, НАП; documents: УП-3, трудова книжка), use related terms naturally, logical flow from one heading to the next. One main keyword in title, H1, first paragraph, one H2 and the meta description. No keyword stuffing.
- Idioms: 1-2 Bulgarian idioms or sayings per post, only where they fit naturally, never in every section. Do not reuse ones already used: "като на длан", "Доверявай се, но проверявай", "времето е пари", "сметката без кръчмаря", "Тук е заровено кучето", "Бързата работа е срам за майстора", "дяволът е в детайлите", "Който пита, не греши", "Капка по капка - вир става".
- Exactly ONE fact box with a real statistic that shows authority: `<p class="fact">... <b>number</b> ... <a href="SOURCE" target="_blank" rel="noopener">3-4 word anchor</a>.</p>` The link must be to a page that proves the number (NOI/nssi.bg, NSI/nsi.bg, НАП, Eurostat, trusted Bulgarian media). Verify it with a web search/fetch before using it.
- Internal links: at least 2 links to calculator pages and 1-2 links to existing blog posts, all on descriptive keyword anchor text (never "тук"). Never link the author name as an anchor for keywords.
- Facts: every legal rule, number and date must be checked with a web search in this run. If unsure, leave it out. Never invent numbers, quotes or experiences. No medical/legal guarantees - point to НОИ/НАП/employer for official answers.
- Google helpful content: written for people first, original value (examples, steps), no filler, no fake claims, no AI disclaimers.
- Punctuation: use regular hyphens "-" instead of em dashes. Bulgarian quotes „ “.
- Do not claim the author has credentials. The author is the pen name Мария Димитрова (handled by the template).

## Checks before pushing
- `grep -rl "—" --include=*.html .` must return nothing.
- Every JSON-LD block parses; every internal `href="/..."` in `<main>` points to an existing file.
- The new post appears on /blog/, in sitemap.xml, on the author page and in the matching calculator page's "Полезни статии".
- Visual check of the new page if a browser is available.
